Demo Run Guide - Agentforce Email Draft

Step-by-step: deploy, verify, run both paths, handle questions. Everything in one place.

Before the Demo - Setup (Do Once)

Step 1 - Deploy metadata to your dev org

From the terminal in your project root. This pushes the email templates, updated prompt template, and flow to your org.

sf org open --target-org <your-org-alias>

# Deploy everything
sf project deploy start --target-org <your-org-alias>

# Confirm deploy succeeded - look for "Deployed successfully"
If you get a prompt template conflict error, go to Setup → Prompt Template Builder → deactivate the existing version first, then redeploy.

Step 2 - Run the data setup script

This creates the Account, Contact, 3 closed historical cases with emails, and the 2 open demo cases.

sf apex run \
  --file scripts/apex/setup_demo_data.apex \
  --target-org <your-org-alias>

Watch the debug log output - it prints the IDs of both demo cases. Bookmark those case URLs now.

If you run the script twice you will get duplicate data. Run it once. If you need to reset, delete the Account "Sunset Aesthetics Medical Group" - it cascades to everything else.

Step 3 - Verify before the meeting

  1. Check the email templates deployed
    Go to Setup → Email Templates → look for folder "Allergan Demo Templates". You should see 3 templates: Credentialing - Medical Director Change, Credentialing - New Practice Enrollment, Product Support - Not Eligible for Products.
  2. Check the Prompt Template is active
    Go to Setup → Prompt Template Builder → open "Custom CSR Response" → confirm status is Published and the template content shows all three TEMPLATE A / B / C options.
  3. Open Demo Case A - confirm no emails on it
    Open the case "Medical Director Change Request - New Director Dr. Patel". Go to the Email tab. Confirm there are zero emails listed. This is your Path A scenario.
  4. Open Demo Case B - confirm the thread is there
    Open "Medical Director Change - Awaiting Form AM-CMD-001". Go to the Email tab. You should see 3 emails: inbound question, outbound reply, inbound follow-up about Dr. Kim travelling and digital signatures. This is your Path B scenario.
  5. Do a dry run of both paths
    Do this 24 hours before the demo, not 5 minutes before. The first call to the LLM can be slow. Verify the output looks good and save a screenshot as backup.
Demo Path A - New Case (No Emails Sent Yet)

What you are showing

A brand-new credentialing case. The CSR has never touched it. The AI recommends the correct email template, fills in the merge fields, and produces a ready-to-send draft - all in one click.

Key point to make: Before Agentforce, a new CSR would open a new case like this and not know which of 1,600 templates to pick. They'd either pick the wrong one, ask a senior colleague, or write the email from scratch. This eliminates all three of those problems.
  1. Open Demo Case A in your org
    Case: "Medical Director Change Request - New Director Dr. Patel"
    Account: Sunset Aesthetics Medical Group | Contact: Dr. Sarah Chen
    "This is a brand new case - it just came in. The CSR has no idea what template to use. Let me show you what happens when they click one button."
  2. Go to the Email tab on the Case
    Click Email tab on the Case record. Click New Email to open the compose window.
  3. Click "Draft with AI"
    The button appears in the email compose footer. Click it. A dialog appears asking you to select a Prompt Template.
    "This is the native Salesforce 'Draft with AI' button - no custom code needed to trigger it. In your org it would be the same button your existing LWC already has."
  4. Select "Custom CSR Response" template
    Click Custom CSR Response → Generate.
    "Behind the scenes, three things are happening simultaneously: the Prompt Template reads the Case attributes - Type, Reason, Description. It queries historical closed cases with the same attributes and retrieves the outbound emails your experienced reps sent. And it presents three template candidates to the LLM and asks it to pick the right one."
  5. Show the output
    The draft should begin with "Selected template: Template A - Credentialing - Medical Director Change Request" then produce the full email with merge fields filled.

    Point out these specific things:
    • The form name AM-CMD-001 is in the draft - exactly as prescribed, not invented
    • The contact name Sarah Chen is filled in correctly
    • The case number is filled in correctly
    • The "5–7 business days" processing time is preserved verbatim from the template
    • The CSR (your logged-in user) name appears in the sign-off
    "Notice that the mandatory language - the form number, the processing timeline, the legal statements - are all exactly as they appear in the template. The AI did not rephrase or invent anything. It selected the right template and filled in the blanks."
  6. Show the human review step
    Point to the draft in the compose window. The CSR can edit any part of it.
    "The CSR sees the draft here. They can change anything they want before sending. Nothing goes out automatically. This is a tool that helps the CSR - it does not replace their judgment."
Demo Path B - Existing Case (Has Reply Thread)

What you are showing

A case that is mid-conversation. The customer has asked a follow-up question. The AI reads the entire thread, understands the context, and drafts the next reply - without repeating what was already said.

Key point to make: This is harder than Path A because the AI must understand what has already been said and what is still unresolved. It needs to address Dr. Kim's travel situation and the digital signature question - two specific things from the last inbound email - without repeating the forms list that was already sent.
  1. Open Demo Case B
    Case: "Medical Director Change - Awaiting Form AM-CMD-001"
    "This case has a three-email thread already. An inbound request, our reply with the forms, and a new inbound from Sarah asking two specific questions: is there a deadline, and can they use a digital signature because Dr. Kim is travelling. Let me show the AI's next reply."
  2. Go to Email tab → New Email → Draft with AI → Custom CSR Response → Generate
    Same sequence as Path A.
  3. Show the output - point out context awareness
    The draft should address both questions from Sarah's last email. Specifically look for:
    • A response to the deadline question
    • A response to the digital signature question
    • No repetition of the forms list that was already sent in the previous reply
    "Notice what the AI did not do: it did not resend the forms list. It read the thread, understood that the forms were already sent, and focused only on the two new questions Sarah asked. That is the grounding working correctly."
Handling Questions During the Demo

Questions they will likely ask - and how to answer them

QuestionWhat they really meanHow to answer
"But this is not using our real templates." They are worried the demo is not representative.
Agree, then reframe: "Correct - I built representative templates based on the scenarios you described in our last meeting. The template selection logic, the placeholder filling, the structure preservation - all of that is exactly how it would work with your real templates. Once you share the structure, I can swap these in about 30 minutes and the demo runs identically with your actual templates."
"How does it know which template to pick?" They want to understand the selection logic - is it random? Rule-based?
Show the prompt template instruction: "The prompt template presents the candidate templates to the LLM and provides the Case attributes. The LLM reads the Case Type, Reason, and Description, then reasons about which template fits best - same way an experienced CSR would. Right now it picks from 3 candidates filtered by record type. When we add the custom tracking field in Phase 2, it will also consider which templates your best reps historically used for cases like this one."
"What if the AI picks the wrong template?" They are worried about reliability and the CSR having to override it.
Acknowledge it will sometimes be wrong, then show the human loop: "It will not always be perfect - especially in the early days before it has usage data. That is why the CSR always reviews the draft before sending. The AI is giving a recommendation, not making a decision. And every time a CSR sends a different template than recommended, we can use that signal to improve the model."
"The tone is not quite right - can we make it more formal / shorter?" They want to see tone control in action.
This is your Phase 2 hook: "Yes - and this is exactly where the tone controls your team built in the LWC come in. We would wire the Shorter / Standard / Longer selector to a parameter in the prompt template. The LLM then adjusts the verbosity while keeping all the mandatory language intact. I can show you that wiring in the next session."
"What about the 1,600 templates - do we need to clean them up?" They are worried about the maintenance burden.
Reframe the cleanup as optional, not required for MVP: "For the initial rollout you do not need to touch the other templates. The AI narrows candidates by record type and folder - so a credentialing case only ever sees credentialing templates. The 1,600 templates do not all compete at once. Cleanup becomes worthwhile in Phase 3 if you want semantic matching across categories, but it is not a prerequisite."
"Does this require Data Cloud?" They want to understand licensing and cost.
Clearly: no, not for this. "Everything you have seen today runs on standard Salesforce objects - Case, EmailMessage, EmailTemplate - and the Einstein Generative AI platform you already have. Data Cloud is not required for this use case. It becomes relevant if you later want semantic search across templates, but that is a future option, not a prerequisite."

What to do if the LLM output looks wrong during the demo

Do not panic. LLM output is non-deterministic - it will sometimes produce something unexpected. Here is how to handle it gracefully in front of the customer.
  1. Wrong template selected
    Say: "It picked Template B here - for your real data it would use the naming convention from your template folders to narrow the candidates more precisely, so the selection would be more accurate." Then show them the prompt template instruction where the selection logic lives.
  2. Placeholder not filled (shows [Contact.FirstName] literally)
    This means the merge field syntax in the prompt template does not match the demo data. Say: "The placeholder syntax here is what I need to confirm with your real templates - that is one of the four things I asked for before this meeting." This is actually a live demonstration of exactly why you need the template structure.
  3. Output is incoherent or very short
    Say: "The LLM is occasionally unpredictable on the first call - let me regenerate." Click Generate again. If it fails twice, move on: "I have a screenshot of a clean run from yesterday - let me show you that while I troubleshoot the org connection."
Always do a dry run the day before and save screenshots of clean output for both paths. These are your insurance policy.
