The Intelligence Model
Two layers working together
Every draft is a blend of policy-accurate template structure and case-specific personalisation. Neither layer alone produces the right output — together they do.

What the Customer Does
Your team's responsibilities after go-live
The Salesforce platform layer — the Flow, CMT object, and Prompt Templates — is built and delivered by Allergan Moxie and the SA team. Once deployed, there are two things your team owns on an ongoing basis.
Short answer: your team manages content, not code

The engineering work — building the Flow, CMT schema, and Prompt Templates — is a one-time delivery. Once it's in your org, your team never touches those. What your team owns is the content that drives the AI: the template bodies and the routing rules that point to them.

Both are edited through standard Salesforce Setup UIs. No deployment, no code, no Salesforce developer needed.

Content Team / Compliance
Email Template Bodies
  • ✏️ Edit template language Go to Setup → Email Templates → Allergan Demo Templates folder. Open any template and edit the body. Changes are live immediately — the next draft generation picks them up with no deployment.
  • 📋 What lives here Form references, SLA numbers, insurance minimums, compliance statements (e.g. Section 4.2, 72-hour AE window). This is the policy-accurate language the AI cannot change or omit.
  • 🔒 Compliance-sensitive templates Patient Adverse Event and Product Access Not Eligible contain mandatory regulatory language. Changes to these templates should go through a compliance review before saving.
  • 👤 Permission required Salesforce user with Manage Public Classic Email Templates permission. No admin or developer access needed.
Salesforce Admin
Routing Rules (CMT Records)
  • 🗺️ Add new scenarios When a new case type requires its own email template: create the EmailTemplate first, then create a CMT record pointing to it. The Flow picks it up automatically — no Flow changes needed.
  • ⚙️ Update routing rules If a Case Type or Reason changes in your org, update the Case Type and Case Reason fields on the CMT record to match. The routing will re-align immediately.
  • 💡 Tune "When to Use" guidance The When To Use field on each CMT record is what the AI reads to choose between two templates with the same Case Type + Reason. If the AI is picking the wrong variant, sharpen this text.
  • 👤 Permission required Salesforce admin access — Setup → Custom Metadata Types → Template Scenario → Manage Records.
How the routing works — multiple templates with the same Case Type + Reason

This is intentional. When a Case Type + Reason combination has both a first-contact and a follow-up template, both CMT records share the same Type and Reason values. The Flow returns all matching records as a candidate pool. The AI then reads the When To Use field on each candidate and selects the best fit based on context — whether there's an existing thread, what the provider asked, which Prompt Template the CSR clicked.

The When To Use field is your control lever. If the AI picks the wrong template, that field is where you tune it — no code change required.

How to add a brand-new scenario (step by step)
1
Write the email template body
Setup → Email Templates → Allergan Demo Templates folder → New Template. Give it a clear DeveloperName (e.g. New_Scenario_Name). Write the policy-accurate body — form references, SLAs, compliance language. Save.
No code Content team
2
Create the CMT routing record
Setup → Custom Metadata Types → Template Scenario → Manage Records → New. Set the Case Type, Case Reason, and Email Template API Name (must match the DeveloperName from step 1 exactly). Write a clear "When To Use" description — this is what the AI reads to choose between candidates.
No code Admin access
3
Test it with a real case
Open or create a case with the matching Case Type and Reason. Click Draft with AI → select the appropriate Prompt Template → Generate. Confirm the draft uses the new template body and the correct "When To Use" guidance routes to it correctly.
No deployment needed
No Flow changes, ever The Prompt Flow does not need to be modified when you add new templates or routing rules. It dynamically queries all active CMT records at runtime. New scenarios are live as soon as the CMT record is saved.
One thing to get right: DeveloperName spelling The CMT field Email Template API Name must match the EmailTemplate DeveloperName exactly — case-sensitive, no spaces. If they don't match, the Flow's lookup returns nothing and the draft will contain "[Body not found — check Email_Template_API_Name__c]". Double-check the spelling when creating new records.
